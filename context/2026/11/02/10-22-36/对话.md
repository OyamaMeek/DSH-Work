### 做了什么

1. 你机器上的 Homebrew node 26.5.1 之前已经坏了：依赖 simdjson 升到 5.1.1 后它找不到 `libsimdjson.33.dylib`，任何 `node` 调用都以 abort 结束。执行 `brew upgrade node` 升到 26.13.0，节点恢复，同时满足 REA 的引擎要求。
2. `npm install -g rea-agents@latest` 把全局包从 6.3.0 拉到 6.8.0。
3. `rea setup --yes --all-detected` 给 claude_code、claude_desktop、codex、cursor、gemini_cli、opencode、copilot_cli、vscode、pi、dsh 十个客户端写入 `rea mcp` 注册，保留 `HOPPER_LAUNCHER_PATH`，Codex 补上 `startup_timeout_sec = 30`、`tool_timeout_sec = 450`，被改写的配置都留了 `.rea.backup`。
4. 技能同步更新到 `~/.agents/skills/` 与 `~/.claude/skills/`。

### 两点须知

- doctor 里 Ghidra、IDA、JADX、Kuna 四项仍为未配置，这几个引擎要自己装并用环境变量指过去，不影响 Hopper 这条路径。
- 桌面应用启动的客户端 PATH 可能不含 `/opt/homebrew/bin`。试过把 `/opt/homebrew/bin/rea` 换成指向绝对 node 的包装脚本，REA 会把这种改写判成 `config_drift`，所以保留 npm 原始的符号链接。哪个客户端报启动失败，就在它的配置里把命令改成 `/opt/homebrew/bin/node`、参数改成 `["/opt/homebrew/lib/node_modules/rea-agents/scripts/rea.mjs","mcp"]`。
