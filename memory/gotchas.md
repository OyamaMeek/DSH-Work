# 任务注意事项

- 教程文档单篇最长 3400+ 行，必须分段读取，不要整篇加载；被删除的文件再次 write 会因文件观察策略报错，需先 read 一次或改用新文件名。
- LibreOfficeKit 直接渲染 pptx 为 PNG 会输出空白页，必须先 convert 转 PDF 再 render；render/convert 不覆盖已存在的输出目录。
- python-pptx 表格行高由渲染器按内容自动扩展，列宽需要按内容长度分配。
- 本机没有 ffmpeg、没有 PyObjC、没有 OpenCV，视频编码只能用 Xcode 自带的 Swift + AVFoundation。
- Swift 编译默认写 /var/folders 会被文件沙箱拒绝，必须把 TMPDIR、CLANG_MODULE_CACHE_PATH、SWIFT_MODULECACHE_PATH 指向工作区目录，并加 `-module-cache-path`。
- AVAssetWriter 稀疏帧会让成片比脚本时长多出几秒，导出时用 `AVAssetExportSession.timeRange` 裁剪。
- AVMutableComposition 里每段音频单独 addMutableTrack 会产生几十条音轨，应合并到同一条音轨再逐段 insertTimeRange。
- PIL 用 Menlo 渲染含中文的代码行会出现方框，需要按行检测 CJK 并切换到 Hiragino 等中文字体。
- Python 脚本不要命名为 `inspect.py` 等标准库模块名，否则 lxml/python-pptx 导入时会循环导入失败。
- PowerPoint 平滑切换的 XML 是 `mc:AlternateContent` 内的 `p159:morph`（2015/09 命名空间），回退写 `p:fade`；缩放定位使用 `pslz:sldZm`，`cId` 要与目标页的 `p14:creationId` 一致。
- 用 bash printf 追加含反引号的 Markdown 会被命令替换吞掉内容，长文本一律先写入文件再用 Python 拼接，或用 edit 工具改文档。
- 反汇编 iOS arm64e dylib 优先用 `dyld_info -disassemble` / `-function_starts`，符号名与函数边界都带标签；`otool -s` 的十六进制输出按列拼接会打乱节内容，直接读文件字节更可靠。
- 混淆二进制的选择子（SEL）在多处 thunk 里硬编码，解析 `adrp+ldr` 到的 selref 表并解码 chained fixup，即可把 4093 个 thunk 还原成选择子名，大幅降低阅读成本。
- ObjC 相对方法表的偏移基准是各字段自身地址：name 相对 &name 且指向 selref 槽，imp 相对 &imp，写成 entry+rel 会整体偏 8 字节，导致全部 imp 错位。
- class_ro.name 与 property/ivar 的字符串指针在 __DATA 中走 chained fixup 编码（高位含 next/auth 位），必须查 fixups 或用低 51 位掩码，直接读 8 字节会拿到无效地址。
- radare2 的 pdc 输出里选择子 trampoline 显示成 `0x666bc0 ()` 或 `fcn.0065cde0 ()`，两种写法都要匹配；thunk 区 0x659880-0x679820 每个 16 字节对应一个固定 selref。
- 用 bash heredoc 跑 Python 时，TS 模板字符串会把 \n 提前变成真换行，导致 Python 语法错误；分析脚本一律写成文件再执行。
- ObjC 方法声明的 label 之间不能加冒号：`-(void)a:(id)x b:(id)y` 正确，`a:(id)x:(id)y` 会被解析成空标签并产生 `a:::` 这类重复 selector。
- Theos 工程里自定义头文件目录要同时加到 CFLAGS 的 -I，Tweak.xm 才能 #import 到 src/Hooks 下的头。
- Theos 可用 Xcode 自带 SDK：把 `$(xcrun --sdk iphoneos --show-sdk-path)` 软链到 $THEOS/sdks/iPhoneOS18.5.sdk，无需另外下载 SDK。
