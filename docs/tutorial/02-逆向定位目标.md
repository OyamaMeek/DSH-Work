# 02 逆向定位目标

写 hook 之前必须先回答三个问题：**哪个类、哪个方法、什么时候被调用**。

## 1. 先看运行时，别急着看二进制

### Frida：动态枚举

```bash
frida-ps -Ua | grep -i aweme         # 确认进程
frida -U -f com.ss.iphone.ugc.Aweme -q
```

```js
// 枚举所有类，找带关键词的
Object.keys(ObjC.classes).filter(n => /TabBar|Feed|Player/.test(n)).slice(0, 40)

// 看某个类有哪些方法
Object.keys(ObjC.classes.AWEMainTabBarController.$ownMethods)

// 拦截并打印调用栈，找“谁调了它”
const m = ObjC.classes.AWEAwemeDetailViewController['- viewDidAppear:'];
Interceptor.attach(m.implementation, {
  onEnter() { console.log(Thread.backtrace(this.context, Backtracer.ACCURATE)
      .map(DebugSymbol.fromAddress).join('\n')); }
});
```

Frida 的优点是快；缺点是方法名被混淆时一样看不到，而且有些 App 会检测 Frida。

### 找按钮回调

界面上的每个按钮最终都是 `target-action`：

```js
// 打印某个视图上所有 control 的 action
const cls = ObjC.classes.AWEPlayInteractionViewController;
Interceptor.attach(cls['- viewDidLoad'].implementation, {
  onEnter() {
    // 等 viewDidLoad 之后再遍历
    setTimeout(() => {
      const self = new ObjC.Object(this.self);
      const walk = (v) => {
        if (v.$class && v.$class.toString().includes('Button')) {
          console.log(v.toString(), v.allTargets().toString());
        }
        const subs = v.subviews();
        for (let i = 0; i < subs.count(); i++) walk(subs.objectAtIndex_(i));
      };
    }, 500);
  }
});
```

拿到 action 的选择子（比如 `onShareButtonTapped:`）之后，直接去 hook 这个选择子，
不用管按钮本身在哪。

## 2. 静态：objc 元数据是最可靠的入口

D 台二进制即使 strip 过，ObjC 的类名、方法名、类型编码也都在。手写解析太慢，
本项目的 `tools/sjj_re/` 就是干这个的：

```bash
python3 tools/sjj_re/objc_meta.py       # → re_meta.json（类、方法、ivar、属性）
python3 tools/sjj_re/gen_source.py      # → reconstructed/headers/*.h
```

核心三步：

1. `__objc_classlist` 里每个指针指向 `class_t`；
2. `class_t + 0x20` 是 `class_ro_t`，里面有类名指针、方法列表指针、属性列表指针；
3. 方法列表是 arm64 的**相对格式**：每个 `method_t` 三个 int32 偏移，
   name 相对 `&name` 指向 `__objc_selrefs` 槽，槽里再指向 `__objc_methname` 的明文选择子。

指针要经过 chained fixups 解码，`dyld_info -fixups` 能导出全量映射：

```bash
dyld_info -fixups Target.dylib > fixups.txt
dyld_info -function_starts Target.dylib > starts.txt   # 每个函数的起始地址与 ObjC 名
```

## 3. 静态：反汇编找调用点

拿到类和方法之后，要看它内部调了什么：

```bash
# 单函数反汇编
objdump -d --start-address=0x3797f4 --stop-address=0x379950 Target.dylib

# 带符号与字符串标注的全量反汇编
dyld_info -disassemble Target.dylib > disasm.txt
```

读 arm64 汇编的三个高频模式：

| 模式 | 含义 |
| --- | --- |
| `adrp x8, 0x95a000; add x8, x8, #0x200` | 取地址 0x95a200 处的 CFString / 全局对象 |
| `adrp x1, page; ldr x1,[x1,#off]; bl _objc_msgSend` | 调用固定选择子（编译器生成的 trampoline） |
| `cbz w0, ...` / `tbz w0,#0,...` | 对 BOOL 返回值做分支，往往就是权限判断 |

混淆过的二进制里，选择子调用会被拆成一个个 16 字节的 trampoline：

```
adrp x1, 0xa25000
ldr  x1, [x1, #0x260]     ; selref 槽
adrp x17, 0xa09000
ldr  x16, [x17, #0x760]   ; _objc_msgSend
braa x16, x17
```

把 selref 槽解出来就能还原成 `objc_msgSend <selector>`，本项目的做法见
`tools/sjj_re/binary.py:describe_call`。

## 4. 案例：找到授权判定

本项目要回答“哪个函数决定功能是否可用”，步骤是：

1. 字符串表里搜 `authorized`，拿到 CFString 地址 `0x95a200`；
2. 用 adrp+add 扫描全 `.text`，找到引用它的代码 `0x379840`；
3. 反汇编该函数，识别出 `objectForKeyedSubscript:@"authorized"` → `boolValue` → `cbz`；
4. `dyld_info -function_starts` 确认函数边界 `0x3797f4`；
5. 扫所有 `bl 0x3797f4`，得到 15 个调用点，确认它是唯一入口。

这套“字符串 → 交叉引用 → 函数语义 → 调用点”的流程适用于几乎所有目标。

## 5. 什么时候必须看 IDA / Hopper

- 控制流被混淆（大量不透明谓词、跳转表）；
- 需要看 Swift 的 witness table；
- 需要理解 Objective-C++ 或 C++ 模板。

本项目的做法是：先用脚本把 95% 的机械工作做完（类图、字符串、调用关系），
只把真正关键的十几个函数丢进 Hopper 看。

## 6. 输出物

定位阶段结束时，你应该有一张表：

| 目标类 | 选择子或函数地址 | 时机 | 用途 |
| --- | --- | --- | --- |
| `AWEAwemeDetailViewController` | `- viewDidAppear:` | 视频页出现 | 注入下载按钮 |
| `0x3797f4` | `BOOL allowed(dict, cap)` | 每次功能判定 | 授权开关 |
| `SJJMediaManager` | `+downloadMedia:...` | 用户点保存 | 改写保存路径 |

有了这张表，第 3 篇的 hook 才有东西可写。
